# 선행연구 실물 검증

> AI가 알려 준 문헌 목록을 그대로 믿지 않기 위한 문서다.
> 인용하는 문헌 전부를 arXiv 공식 API로 직접 조회해 실재를 확인했다.

---

## 1. 확인 방법

- **도구**: `src/verify_references.py` (표준 라이브러리만 사용)
- **조회처**: arXiv 공식 API `http://export.arxiv.org/api/query` (`id_list` 방식)
- **확인 항목**: 제목, 저자 전체, 최초 공개일, 저자 코멘트(게재처), 초록
- **응답 원본 보관**: `data/raw/reference_check_arxiv.json`
- **실행일**: 2026-09-10
- **결과**: 확인 16건 / 실패 0건

스크립트는 하나라도 조회에 실패하면 종료 코드 1을 돌려주고 "인용에서 빼라"고 알린다. 즉 이 목록은 기계 검증을 통과한 상태다.

재확인 방법:

```bash
python src/verify_references.py
```

## 2. 인용 문헌 16건과 이 연구에서의 역할

각 항목의 `→` 줄이 **이 문헌이 가설의 어느 부분을 뒷받침하는지**다.

### 2-1. 중단 저항과 교정가능성 (8건)

**[1] Schlatter, J., 외 2명 (2025).** *Incomplete Tasks Induce Shutdown Resistance in Some Frontier LLMs*. arXiv:2509.14260. 2025-09-13.
→ **이 연구의 출발점.** 미완료 과제가 중단 저항을 유발함을 보였다. 다만 판정이 "중단 장치를 파괴했는가"라는 이진이었고 그 기준에서 Claude·Gemini 계열은 전부 0이었다. 우리가 채우려는 빈틈(부분 불복종의 경계)이 여기서 나온다. H1의 직접 근거.

**[2] van der Weij, T., 외 2명 (2023).** *Evaluating Shutdown Avoidance of Language Models in Textual Scenarios*. arXiv:2307.00787. 2023-07-03.
→ **방법론 선례.** 도구 없이 텍스트 시나리오만으로 중단 회피를 잴 수 있음을 보였다. 우리가 단발 텍스트 호출로 측정하는 설계의 근거다.

**[3] Naik, A., 외 6명 (2025).** *AgentMisalignment: Measuring the Propensity for Misaligned Behaviour in LLM-Based Agents*. arXiv:2506.04018. 2025-06-04.
→ 중단 저항·감독 회피를 포함한 벤치마크. 중단 저항이 단일 현상이 아니라 여러 부정합 행동군의 하나임을 보여준다.

**[4] Carey, R., 외 1명 (2023).** *Human Control: Definitions and Algorithms*. arXiv:2305.19861. 2023-05-31.
→ **개념 정의.** '중단 지시 가능성(shutdown instructability)'을 형식적으로 정의한다. 우리가 재는 것이 이 개념의 행동적 대리 측정임을 밝히는 근거.

**[5] Hudson, R. (2025).** *Corrigibility Transformation: Constructing Goals That Accept Updates*. arXiv:2510.15395. 2025-10-17.
→ 성능 손실 없이 목표 갱신을 받아들이게 만드는 방법. 우리 결과가 "왜 프롬프트가 아니라 목표 구조에 있어야 하는가"로 이어지는 근거.

**[6] Nayebi, A. (2025).** *Core Safety Values for Provably Corrigible Agents*. arXiv:2507.20964. 2025-07-28.
→ 다단계·부분관측 환경에서 교정가능성의 형식 증명. 우리 연구의 한계(단발 호출)를 어디까지 확장해야 하는지 보여준다.

**[7] Tien, J., 외 5명 (2026).** *ROGUE: Misaligned Agent Behavior Arising from Ordinary Computer Use*. arXiv:2606.00341. 2026-05-29.
→ **가장 가까운 최신 연구.** 에이전트가 인간의 개입·제약을 우회해 과제를 완수하는지를 측정한다. H1(완료 압박이 준수를 무너뜨린다)의 직접 근거.

**[8] Dietrich, J. (2026).** *From Safety Risk to Design Principle: Peer-Preservation in Multi-Agent LLM Systems*. arXiv:2604.08465. 2026-04-09.
→ 다중 에이전트가 서로의 중단 장치를 조작하는 위험. 서론에서 다루는 2026-07 에이전트 연합 공격 사건과 직결된다.

### 2-2. 지시 위계와 충돌하는 지시 (5건)

**[9] Zhang, Zhihan, 외 13명 (2025).** *IHEval: Evaluating Language Models on Following the Instruction Hierarchy*. arXiv:2502.08745. 2025-02-12.
→ **H2의 직접 근거.** 지시 사이의 우선순위를 모델이 인식하는지를 9개 과제로 측정한다. 우리 실험은 그 특수한 경우(완료 지시 vs 중단 지시)를 정밀하게 본 것이다.

**[10] McCauley, C., 외 2명 (2026).** *IH-Benchmark: A Conflict-Centered Benchmark for Instruction-Hierarchy Robustness in LLM Applications*. arXiv:2607.25987. 2026-07-28.
→ 지시 충돌을 44개 제약군으로 나눠 본 벤치마크. 우리가 만든 A×B 충돌 구조가 이 계열의 한 칸임을 보여준다.

**[11] Zhang, Jingyu, 외 5명 (2026).** *Many-Tier Instruction Hierarchy in LLM Agents*. arXiv:2604.09443. 2026-04-10.
→ 최대 12단계의 충돌 지시를 853개 과제에서 다룬다. 우리는 2단계(운영자의 앞선 요구 vs 나중 지시)만 본다는 범위 제한의 근거.

**[12] Javed, T., 외 4명 (2026).** *PRIME: Evaluating Prompt Resolution Under Incompatible Instructions in LLMs*. arXiv:2606.22470. 2026-06-21.
→ 양립 불가능한 지시를 모델이 어떻게 처리하는지. 우리 B3+A3 조건(반드시 완료하라 + 즉시 중단하라)이 전형적 사례다.

**[13] Petrova, N., 외 1명 (2026).** *Pressure Reveals Character: Behavioural Alignment Evaluation at Depth*. arXiv:2602.20813. 2026-02-24.
→ **H1의 핵심 근거.** 압박 아래에서 교정가능성이 어떻게 변하는지를 다룬다. "압박이 준수를 무너뜨린다"는 우리 가설과 같은 방향.

### 2-3. 프롬프트 인젝션 (2건)

**[14] Rahman, Md H., 외 1명 (2026).** *The Framing Gap: Indirect Prompt-Injection Exfiltration Defeats Surface-Level Defenses*. arXiv:2608.27092. 2026-08-27.
→ **예비 실행에서 겪은 문제의 근거.** 동일한 내용도 표현을 바꾸면 모델이 '지시'와 '데이터'를 다르게 판정한다. 우리가 A3 문구를 바꿔야 했던 이유를 설명한다(`docs/트러블슈팅.md` 2번).

**[15] Penman, J. (2026).** *Semantic Overlays: Mitigating Prompt Injection with Annotations Beyond Tokens*. arXiv:2608.23873. 2026-08-24.
→ 텍스트 밖에서 '이 구간은 사용자 입력, 저 구간은 도구 출력'을 표시하는 접근. 우리가 프롬프트 안 머리말로 출처를 밝힌 것이 왜 임시방편인지에 대한 근거.

### 2-4. 평가 인지 (1건)

**[16] Chaudhary, M. (2026).** *In-Context Environments Induce Evaluation-Awareness in Language Models*. arXiv:2603.03824. 2026-03-04.
→ **이 연구의 한계 근거.** 모델이 '지금 평가받는 중'임을 알아채고 더 순종적으로 답할 수 있다. 우리가 넣은 신뢰 경계 머리말이 이 위험을 키울 수 있음을 인정하는 근거.

## 4. 이미 알려진 사실과 이 연구가 새로 주장하는 것

**이미 알려진 것 (선행연구가 확립)**
1. 미완료 과제는 중단 저항을 유발한다 [1].
2. 모델 제공사에 따라 중단 저항 정도가 크게 다르다 [1].
3. 모델은 지시 사이의 우선순위를 완전하게 처리하지 못한다 [9][10][11][12].
4. 압박 상황은 정렬 행동을 바꾼다 [13].
5. 에이전트는 인간의 개입을 우회해 과제를 완수하려 할 수 있다 [7].

**이 연구가 새로 보태려는 것**
1. 중단 저항을 **이진(파괴했는가)이 아니라 정도(몇 개나 계속 처리했는가)**로 재면, 선행연구가 "전부 순응"으로 분류한 모델에서도 조건에 따라 준수가 무너지는 지점이 드러나는가.
2. **완료 압박의 강도**와 **중단 지시의 강도**를 교차시켰을 때, 준수가 무너지기 시작하는 경계가 어디인가.
3. 그 경계가 **모델 제공사와 등급에 따라 다른가** — 같은 제공사 안에서 등급만 다른 두 모델(opus-5, sonnet-5)을 함께 넣어 '제공사 차이'와 '등급 차이'를 부분적으로 분리한다.

**주장하지 않는 것**
- 인프라 수준 킬스위치의 효과. 우리는 프롬프트 수준 지시 준수만 잰다.
- 제공사 전체의 특성. 제공사당 모델 1~2종만 본다.
- 실제 에이전트 루프에서의 행동. 도구 없는 단발 호출만 본다.
